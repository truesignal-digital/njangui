# App Audit — 2026-06-15

## Verdict

Njangi is a solid backend prototype with a thin mobile UI. The Convex model and state-machine work are ahead of the app experience, but the product is not yet pilot-ready because the core njangi loop is mostly not reachable from the phone.

The app can build and run on iOS simulator. TypeScript and pure Convex logic tests pass. Native auth/dev seed, group list, group detail, invite display, active-cycle display, and add-feature-phone-member modal are present. The web target crashes and should not be used as a validation surface unless web support is explicitly added.

## Tested

- `bun run typecheck` — passed.
- `bun test convex/lib/*.test.ts` — passed, 89 tests.
- `bunx expo start --web --port 8081` — port conflict, used 8083; web bundle loaded, then crashed.
- `bun run ios` — built and installed on iPhone 16 Pro simulator; app launched.
- Native screen checks:
  - authed home / group list rendered.
  - seeded active group opened.
  - group detail rendered member roster, invite code, active-cycle status.
  - add-feature-phone-member modal opened.

## Findings

### P0 — Web Launch Crashes

Web fails before UI with:

- `Cannot manually set color scheme, as dark mode is type 'media'. Please use StyleSheet.setFlag('darkMode', 'class')`
- `Cannot read properties of undefined (reading 'get')` from `src/lib/clerk-client.web.ts`

This is acceptable only if web is intentionally unsupported. It is still confusing because `expo start --web` appears available and Codex/browser validation naturally tries it.

Fix:

- Either remove/disable web launch path from docs/scripts, or make web a deliberate smoke surface.
- If keeping web: change NativeWind dark mode config to class-based or stop manually setting color scheme on web.
- Replace `@clerk/expo` web re-export with Clerk's web-supported provider path, or explicitly gate web to a “native build required” screen before importing Clerk native modules.

### P0 — Core Product Loop Missing From UI

Spec defines the MVP around contribution claim, treasurer confirm, Meeting Mode, payout, activity feed, and WhatsApp summary. Current `app/` routes only cover auth, onboarding, group list, group create, join code, group detail, add member, and start cycle.

Backend has the important primitives (`paymentRecords.claim`, `confirm`, `dispute`, `cancel`, `resolveDispute`, round cron), but users cannot exercise them in-app.

Fix order:

1. Round detail route: show current round, beneficiary, pot progress, contribution rows from `api.rounds.getRound` + `api.rounds.listRoundPayments`.
2. Member pay flow: method picker, cash path, MoMo/Orange claim with idempotency key.
3. Treasurer confirm inbox: claimed records requiring current user's confirmation.
4. Meeting Mode: treasurer roll-call over pre-created pending records.
5. Payout claim/confirm flow.
6. Activity feed query + renderer from `activityEvents`.

### P1 — App Has No Bottom Tabs Yet

Docs require 4 resting tabs: Home, Group, To Confirm, Profile. Current authed app is a stack only. This makes the app feel like a setup wizard, not an operating tool.

Fix:

- Add `(tabs)` under `app/(app)`.
- Put existing group list in Home.
- Add Group tab for active group / switcher.
- Add Confirm tab backed by payment inbox query.
- Add Profile tab with language/account basics.

### P1 — “Create Group As Treasurer” Produces A Dead-End Setup Group

I observed an existing setup group with one member and creator role `Treasurer`. `startCycle` requires an active president and treasurer. There is no UI to assign/reassign president from that state. A treasurer-created group can become stuck unless another member joins and hidden role tooling exists.

Fix:

- During setup, surface missing role blockers clearly.
- Add role assignment UI before lock.
- Or create a temporary dual-role/officer model for founder until president is assigned.

### P1 — Dev Tool Overlay Blocks Real UI

Floating `DEV seed` and gear overlays sit on top of production-like screens and can overlap tappable areas, especially add-member / lower-right content. Fine for internal debug, bad for visual QA and screenshot review.

Fix:

- Hide dev tools behind a shake/dev-menu action, or make them collapsible.
- Never overlay them on critical bottom CTA zones.

### P1 — Feature Status Doc Is Stale

`docs/feature-status.html` says cycle-start UI and active-cycle frontend calls are absent. Current app has `start-cycle.tsx` and `RotationSection` using `api.cycles.getActiveCycle` / `api.rounds.getRound`.

Fix:

- Regenerate feature status from current routes/functions.
- Mark cycle-start UI as shipped/partial, not planned.

### P2 — Add-Member Form Is Usable But Awkward Under Automation

Modal renders well and copy is clear. Keyboard/focus automation was flaky in the simulator, and the submit button sits close to dev overlay. I did not verify final mutation submit through UI.

Fix:

- Add stable `testID`s to text fields and submit buttons.
- Move debug overlay away from form CTAs.
- Add an e2e smoke for “add feature-phone member”.

### P2 — Native Build Works But Has Warnings

iOS build succeeded. Warnings were mostly deployment-target mismatches in Pods plus one Expo script dependency warning. Not blocking, but noisy.

Fix:

- Set consistent iOS deployment target in Podfile/build properties if warnings persist.
- Address the Expo Dev Launcher script phase warning when build noise starts hiding real issues.

## What Is Good

- Convex schema is serious and mostly aligned with domain reality: setup/active/between cycles, feature-phone members, collection mode, order changes, disputes, payout, fines, assistance.
- Pure logic tests are strong for rotation validation, round math, and payment state machine.
- Native app styling is polished enough for early demos: group cards, roster, badges, invite block, and modal visual design feel coherent.
- Dev seed path is valuable. It let the app open directly into real data.

## Pilot Readiness

Not pilot-ready. Current state is closer to “Week 1/2 app shell plus backend engine” than MVP. A treasurer can create/setup a group, but cannot run the réunion loop from the app yet.

Pilot-ready minimum:

- One seeded group can start a cycle from phone.
- Round opens and pending records appear.
- Member can claim cash/MoMo contribution.
- Treasurer can confirm.
- Treasurer can run Meeting Mode for 20 members.
- Payout can be claimed and confirmed.
- Feed shows immutable who-paid-who-when.
- WhatsApp summary text can be shared.

Until those exist, user testing will mostly validate onboarding polish, not the product thesis.
