0 · Qui confirme l'argent du trésorier ? logique métier

Vous avez trouvé un vrai trou. Dans le code (convex/rounds.ts:240, paymentRecords.ts:562) :

Membre ordinaire — payer = membre, payee = trésorier → le membre déclare, le trésorier confirme. ✓ contre-partie réelle
Trésorier lui-même — payer = payee = trésorier → isSelfRecord → confirmé instantanément, par personne. Seule trace : une ligne «auto-confirmé» dans le fil d'activité.
▼ proposition
Règle de contre-signature — un enregistrement «self» reçoit un vrai confirmateur :
1. le président confirme les cotisations du trésorier (la mécanique «confirmer au nom de» existe déjà dans confirm) ;
2. si président = trésorier → le bénéficiaire du tour confirme ;
3. si les trois rôles sont la même personne → auto-confirmation conservée, mais étiquetée en gros «auto-confirmé (aucun contre-signataire)» dans le ledger ET le mode réunion.

Symétrie déjà saine : la remise du pot est contre-signée (le bénéficiaire confirme le payout, minuterie anti-fuite de 7 j) — l'exposition est donc par cotisation, pas sur le pot entier.

1 · Tuer l'onglet «À confirmer» navigationeffort moyen

Décision proposée : 4 onglets. L'état normal du tab est «rien à faire» — un slot de navigation sur cinq qui apprend aux gens à l'ignorer. Remplacement : une pile d'actions en haut de l'Accueil (0 pixel quand vide), badge compté sur l'onglet Accueil, et un écran poussé «Tout voir» pour les listes longues.

  • Icône actuelle = CheckCircle («fait») pour un onglet «action requise» — même glyphe, deux sens opposés
  • Badge d'onglet rouge plateforme, hors système de tokens
  • Les rangées n'affichent ni l'heure de la déclaration ni la fenêtre d'objection — la raison d'être de l'écran
  • Montant noyé au milieu d'une ligne de texte, contre la posture money-first du nouvel Accueil

Le pill «Vérifier» route vers le détail du paiement — jamais de confirmation en un tap depuis une liste (posture server-truth conservée).

Sources : Deel — upcoming actions sur l'accueil · Chime — pending card, montant en tête · PayPal — section Pending sans tab · Satispay — liste poussée hors tab bar

Coût : déplacer inbox.tsx vers /confirmations, section Accueil, badge stylé — moyen, zéro backend.

4 · Calendrier hybride effort moyen

Le tab n'a aucun calendrier visuel — juste du texte. Le jour de paie (le meilleur moment de la surface) a la même typographie qu'une cotisation, et les rangées ne sont même pas tappables.

  • «estimé» et «passé» partagent le même gris — deux sens, un seul style
  • Aucun repère «aujourd'hui», aucun saut de mois
  • Zéro identité de groupe sur les rangées (mur monochrome dès 3 groupes)

Hybride : héros «Prochaine échéance» (gros numéro du jour, «dans 3 jours», montant) → grille de mois repliable avec points teinte-groupe + tick vert les jours de paie → agenda en rail timeline (plein=confirmé, anneau accent=prochain, tirets=estimé) avec fond teinté succès sur les jours de paie. Rangées tappables → groupe.

Sources : Rocket Money — grille + marqueurs · Hyundai Card — grille repliable · Klarna — échéances relatives · Afterpay — rail

Coût : zéro backend (myAgenda déjà souscrit) ; grille + rail + héros — moyen.

5 · «Ma cotisation» = timeline de cycle de vie effort moyen

Vos deux plaintes sont dans le code : l'état n'est porté que par des chips de 12 px, et le chip «déclaré» emprunte la couleur de marque (accent doré) — en mode clair, le fond de «déclaré» est littéralement la même valeur que celui de «contesté». Et quand c'est réglé : deux coches vertes qui disent la même chose.

Réponse standard fintech (Wise, Revolut, Fidelity) : une timeline verticale par enregistrement — étapes faites en fines lignes horodatées, étape courante en phrase nommant qui agit («En attente de confirmation par Mama Ngozi»), et la timeline finie EST le reçu. Retonage global : accent = action/CTA seulement ; pending=contour, déclaré=neutre, confirmé = le seul fond coloré (succès), contesté=warning. Multi-mains : «1ʳᵉ main · 5 000 F» par bloc.

Sources : Wise — l'étape courante en prose · CVS — stepper monochrome, zéro fond teinté · Wise — la timeline devient le reçu · Revolut — compteur d'étapes dans le titre

Coût : zéro backend (les horodatages existent déjà côté serveur, jetés par l'UI) ; nouveau composant timeline ~120 lignes + retonage badge partout — moyen.

6 · Mode réunion = cérémonie effort moyen

La plomberie (file d'attente offline, idempotence) est bonne — mais le trésorier qui compte du liquide dans une salle n'a aucun total encaissé/attendu à l'écran avant de taper «Terminer». Et un effleurement de rangée annule un pointage sans confirmation.

  • Le montant disparaît d'une rangée dès qu'elle est pointée
  • Édition de montant = long-press caché, zéro découvrabilité
  • Pot complet ressemble exactement à 3/12 — aucun moment

Héros = anneau de progression 96 px (teinte du groupe, le «one bold use») avec 8/12 au centre + total encaissé à droite. Rangées en deux sections — «À encaisser» / «Encaissé» (les pointés coulent en bas, animés). Annulation = bouton dédié + feuille de confirmation (Partiful). Crayon visible sur le montant. Pied collant réconciliateur : «Terminer — reste 120 000 F (4 membres)» → devient primaire «Clôturer — le compte est bon» à 100 % avec un seul burst de confetti (Klima). Écran final = cérémonie : gros pot, garde nommée, carte bénéficiaire, «À lire à voix haute».

Sources : Partiful — check-in + feuille d'annulation · How We Feel — l'anneau EST l'écran · Klima — 100 % = confetti · Splitwise — pied réconciliateur · Jobber — crayon sur le montant

Coût : présentation pure — mutations, file, idempotence intactes. Moyen.
